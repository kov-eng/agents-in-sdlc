まず、プロジェクトに小さな機能を追加しました。より大きな変更には、さらにしっかりとしたプロセスが必要です。GitHub Copilot CLI は組織の既存のフローに沿って動作し、適切なものを適切な方法で構築できるように設計されています。このレッスンから数回にわたり、一般的なエージェント主導の開発プロセスに沿って、新機能を作成し、コードが有効で期待どおりに動作することを確認し、最終的にプロジェクトにマージします。

> [!NOTE]
> 機能の作成を続ける間、同じ会話とブランチを使います。通常は、扱うファイルの種類ごとに異なるブランチや PR を使用しますが、ここでは主な概念に集中するため手順を簡略化します。

このレッスンでは、次のことを行います。

- GitHub issue から Copilot の新しい会話を開始します。
- Plan モードで要件を定義します。
- Autopilot モードで新機能を実装します。
- コードをレビューします。
- ポート フォワーディングされたブラウザーで機能を手動で検証します。

この機能の作成を続けながら、リポジトリの指示を更新し、既存の `quality-checks` スキルをカスタマイズし、MCP による検証を追加して QA エージェントを作成し、機能 PR を開きます。

## シナリオ

Tailspin Toys のカタログは拡大しており、訪問者がカテゴリとパブリッシャーでゲームを絞り込めるようにしたいと考えています。バックログの issue には機能の概要がありますが、複数カテゴリの組み合わせ方など、コーディング前に合意する詳細があります。Plan モードで決定事項を整理し、Autopilot にスコープを限定した実装を許可します。

## 背景

AI コーディング エージェントを開発フローに追加しても、基本は変わりません。むしろ一層重要になります。多くの開発者は、次のような流れで作業しています。

1. 作業内容を説明する issue から開始します。
2. 構築するものの計画を立てます。
3. コードを作成してレビューします。
4. テストを実行してコードを検証します。
5. 新機能を手動で検証します。
6. プルリクエスト (PR) を作成します。
7. コードレビューが完了し、継続的インテグレーションが成功したら、コードをマージします。

> [!NOTE]
> 正確な手順はチームや組織によって異なりますが、ほとんどの場合は上記の流れを調整したものです。

この標準的な進め方に従うことで、AI が生成したコードが要件を満たし、手書きのコードと同じレビュー プロセスを通るようにできます。

## 会話モード

**会話モード**は、エージェントにどの程度の自律性を与えるかを制御します。<kbd>Shift</kbd>+<kbd>Tab</kbd> を押してモードを切り替えます。

- **Interactive**: あなたとエージェントが協力します。エージェントは変更を提案し、次に進む前に入力を待ちます。
- **Plan**: エージェントが先に計画を作成します。プロジェクト ファイルを編集することはできません。
- **Autopilot**: エージェントが自律的にコードを書き、テストを実行し、タスクが完了するまで反復します。

まず Plan モードで開始して計画をレビューし、その後 Autopilot で実装します。

## issue から開始する

フィルタリング機能の作業を始める前に、Codespace に戻り、リポジトリとターミナルを準備します。

1. Codespace に戻ります。停止している場合は、再起動してから続けます。
2. 星評価の PR がマージ済みであることを確認します。
3. ターミナルが開いていない場合は、<kbd>Control</kbd>+<kbd>\`</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>\`</kbd> (Windows/Linux) を押します。
4. `main` を更新してから、フィルタリング作業用のブランチを作成します。

   ```bash
   git checkout main
   git pull --ff-only
   git checkout -b game-filters-cli
   ```

5. Copilot CLI を起動します。

   ```bash
   copilot --yolo
   ```

6. <kbd>Tab</kbd> を 2 回押して **Issues** タブを開きます。
7. <kbd>A</kbd> を押してすべての issue を表示します。
8. 矢印キーで **Allow users to filter games by category and publisher** というタイトルの issue を選択します。
9. <kbd>C</kbd> を押して issue をプロンプトに追加し、**Session** タブに戻ります。

プロンプトが `#7` (または同様の番号) で始まることを確認します。`#` を使うと、GitHub 上の issue やプルリクエスト (PR) をコンテキストに追加できます。

## フィルタリング機能を計画する

計画を立てることで、機能を実装したりタスクを実行したりする前に、方法を定義できます。複雑な作業では、事前に計画を立てるとよいでしょう。Plan モードに切り替えて Copilot に計画を作成してもらいます。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Plan モードに切り替えます。プロンプトの下にあるモード表示が **Plan** になっていることを確認します。
2. 前の手順で追加した issue 参照の後に、次のプロンプトを入力します。

   ```plaintext
   Create a plan for implementing this feature.
   ```

Copilot はプロジェクトを調べて、最適な方法を決め、計画を作成します。

3. フィルタリング機能の動作について質問されたら、希望する動作を回答します。唯一の正解はありません。
4. 計画が完成したら、<kbd>Control</kbd>+<kbd>E</kbd> (Mac) または <kbd>Ctrl</kbd>+<kbd>E</kbd> (Windows/Linux) を押して計画を展開します。
5. 計画を上下にスクロールしてレビューします。
6. 判断と異なる部分があれば、Copilot に修正を依頼します。

## Autopilot を承認する

計画を作成してレビューしたら、実装に進みます。Autopilot を使って Copilot に作業を任せます。

Autopilot を使うと、Copilot は作業が完了したと判断するまで問題に取り組み、反復します。

1. **Accept plan and build on autopilot (recommended)**、またはインストールしたバージョンで同様の名前が付いたオプションを選択します。
2. プロンプトの下にあるモード表示が **Autopilot** になっていることを確認します。
3. Copilot が作成した計画に沿って反復し、コードを生成してテストを実行する様子を確認します。

> [!NOTE]
> 承認すると、実装がすぐに開始される場合があります。まず計画をレビューしてください。Copilot から依存関係の不足やポートの競合が報告された場合は、チェック完了と見なす前にセットアップの問題を解決してください。

## 実装をレビューして検証する

コードが生成されたら、他のコードと同様にマージ前のレビューが必要です。コードを確認し、サイトを実行してすべて正常に動くことを確かめましょう。

1. <kbd>Shift</kbd>+<kbd>Tab</kbd> を押して Interactive モードに切り替えます。モード表示が **Plan** または **Autopilot** ではないことを確認します。
2. `/diff` を入力し、フィルタリングの実装とテストを確認します。
3. 結果を issue と計画時の決定事項と比較します。
4. コードのレビューが終わったら、<kbd>Esc</kbd> を押して差分ビューを終了します。
5. プロジェクトのチェック結果を確認し、失敗があれば Copilot に修正を依頼します。

## 新機能を試す

コードに問題がないように見えても、実際に動作するでしょうか。前回と同じようにアプリを起動し、Codespaces のポート フォワーディングからサイトを開きます。

1. Copilot に次のように依頼してアプリを起動します。

   ```plaintext
   Start the app so I can try the filtering feature in my browser. Tell me the URL and leave the server running.
   ```

2. Codespaces でポート `4321` が利用可能になったら、**Open in Browser** を選択します。
3. 計画で決めたカテゴリ フィルタリング、パブリッシャー フィルタリング、および組み合わせを試します。
4. リセット時と検索結果がない場合の動作が、issue と決定事項に合っていることを確認します。
5. Codespace に戻り、起動した開発サーバーを Copilot に停止するよう依頼します。

## まとめと次のステップ

異なる会話モードを使って機能を作成し、レビューしました。このレッスンでは、次のことを行いました。

- GitHub issue から Copilot の新しい会話を開始しました。
- Plan モードで要件を定義しました。
- Autopilot モードで新機能を実装しました。
- コードをレビューしました。
- ポート フォワーディングされたブラウザーで機能を手動で検証しました。
