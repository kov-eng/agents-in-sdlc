GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイルの編集、コマンドの実行などを自律的に行います。VS Code の Copilot Chat では、作業がマシン上でリアルタイムに進むため、各ツール呼び出しやファイル編集を確認できます。差分をインラインでレビューし、個々の変更を承認または取り消したり、エディターを離れずに追加のプロンプトを送って作業を調整・拡張したりできます。

この演習では、次のことを行います。

- アクセシビリティ エージェントの作業をリアルタイムで監視します。
- 提案されたファイル編集を確認して承認します。
- セッションの途中でエージェントに指示し、ハイ コントラストに加えてライト モードの切り替え機能を追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ カスタム エージェントが、ハイ コントラスト モードを実装しています。作業中に、デザイン チームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライト モードの切り替え機能も追加したいとのことです。最初から会話をやり直すのではなく、既存のセッションに追加の作業を指示します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行う各ステップが表示されます。調査するファイル、実行するコマンド、提案する編集を確認できます。各ファイル編集は差分と **Keep** / **Undo** のコントロールとともにチャットにインラインで表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、各ツール呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナル コマンドが表示されます。
3. エージェントがファイルの編集を提案すると、差分がインラインで表示されます。
    - 変更を承認するには **Keep** を選択します。
    - 変更を取り消し、エージェントに再度作業させるには **Undo** を選択します。
4. チャットの上部にある **Files changed** の表示を開くと、このセッション中にエージェントが変更したファイル一式も確認できます。

> [!NOTE]
> たとえばターミナル コマンドの実行などでツールの使用許可を求められると、エージェントは一時停止して **Allow** プロンプトを表示します。実行してもよいコマンドだけを許可してください。

5. エージェントがハイ コントラスト モードの実装を完了するまで待ちます。最後に、変更内容をまとめたメッセージが表示されます。

## ライト モードを追加するようエージェントに指示する

ハイ コントラスト モードができたら、同じ会話でライト モードの切り替え機能を追加します。同じチャット セッションを続けることで、エージェントは前の作業で得たコンテキスト (変更したコンポーネント、スタイルの方針、設定した local storage の使い方など) を保持しています。

1. Copilot Chat の入力欄に次の追加プロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは前の作業を引き継ぎ、すでに加えた変更を調べて、ライト モードの追加を提案します。
3. 変更が適用されるたびに、ハイ コントラストの場合と同様に確認します。各差分で **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合 (たとえば、好みと異なる方法でトグル UI をリファクタリングしようとした場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、追加のメッセージで意図を伝えます。

> [!TIP]
> 作業中のセッションに指示するほうが、最初からやり直すより早く済みます。追加のプロンプトで調整を依頼できます (「CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使ってください」など)。方向を修正できます (「3 つ目のトグルは追加せず、ライト モードを既存の設定パネルに組み込んでください」など)。作業範囲の拡張も依頼できます (「両方のトグルにキーボード ショートカットも追加してください」など)。

## 作業内容を確認する

変更をコミットする前に、エージェントが変更したファイル全体を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されているはずです。
3. 変更されたファイルをいくつか開き、差分を確認します。カスタム エージェントが使ったアクセシビリティの手法 (ARIA 属性、キーボード ナビゲーション、セマンティック HTML、local storage による永続化) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して調整しました。各ファイルの編集を確認して承認または拒否し、コンテキストを保ったまま追加のプロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムで監視する方法。
- 個々のファイル編集を承認または拒否する方法。
- 追加のプロンプトを使って、進行中のセッションを調整する方法。

[次のレッスン][next-lesson]では、アクセシビリティの作業をプルリクエストとして公開し、このラボを通してローカルのカスタム エージェントが行った変更をレビューします。
